### 🥇 1. Which cloud infrastructure component do you think is the most important? Why?
I think compute is the most important component. It's the resource that actually processes everything — without it, storage just holds idle data and networking has nothing to deliver. Every other component exists to support compute in doing its job.

### 🐧 2. How does Linux support cloud computing?
Linux is the backbone of most cloud infrastructure because it's open-source, lightweight, and highly customizable. Almost every major cloud provider runs Linux-based virtual machines under the hood, and the command-line tools I used in this lab (`lscpu`, `free -h`, `df -h`) are the same ones real engineers use to inspect and manage servers at scale.

### 📄 3. Why is technical documentation important before deploying infrastructure?
Documentation gives engineers a clear picture of what resources are available before they commit to a design. Without it, teams risk under-provisioning or over-provisioning a server, missing security gaps, or making decisions based on guesswork instead of actual specs. It also makes the environment easier to hand off to other engineers.

### 🌱 4. What new skills did you learn during this laboratory activity?
I learned how to inspect a Linux server's hardware and software details directly from the terminal, and how to interpret that output in terms of real infrastructure planning. I also learned how the same cloud service appears under different names across AWS, Azure, and GCP, and practiced creating a basic cloud architecture diagram.

### 📈 5. How has your GitHub portfolio improved after completing this mission?
My portfolio now includes a second, more technical laboratory folder that shows I can go beyond basic Linux navigation into actual infrastructure assessment. It's more organized, with clearer documentation structure, and demonstrates skills that are directly relevant to real cloud engineering work.
