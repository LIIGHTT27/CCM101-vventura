# Mission Reflection

Automation is important when managing hundreds of cloud servers because it makes work faster and easier. Instead of performing the same tasks manually on every server, a script can execute commands automatically. It also reduces human errors and helps cloud engineers manage their systems more efficiently. Automation is useful for backups, updates, and system maintenance.

Automation can also be dangerous if the script contains a mistake. For example, if a destructive command is accidentally included in a script and executed on 1,000 servers, it could cause serious damage or data loss. To avoid this, scripts should be tested carefully before deployment. Having backups and checking commands before running them are also important.

Writing a Bash script is different from creating a Docker Compose YAML file. A Bash script contains commands that execute step by step, such as creating folders and compressing files. Docker Compose YAML describes the services and configurations needed to run an application. I learned that Bash is useful for automation, while Docker Compose is helpful for managing containers.

Before starting the laboratory activities, I had only a basic understanding of cloud computing. I thought it was mainly about storing files and using applications online. After completing nine missions, I learned about infrastructure, cloud-native applications, databases, deployment, operations, security, and automation. These activities helped me understand how different cloud technologies work together and improved my technical skills.

The role I enjoyed most was the Cloud Automation Engineer because I found it interesting to create scripts that perform tasks automatically. In this mission, I learned how to create a backup script, use chmod to make it executable, and schedule tasks using cron. I enjoyed seeing how automation can save time and make work easier. This experience motivated me to learn more about cloud computing and Linux commands.
