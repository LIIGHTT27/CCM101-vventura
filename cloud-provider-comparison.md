# ⚔️ Cloud Provider Showdown
### *AWS vs. Microsoft Azure vs. Google Cloud Platform*

> Same infrastructure, different names. A cloud engineer must be fluent in translating between providers. This comparison maps the core services of the three biggest players in the market.

## 🧭 Guide Questions

### 1️⃣ Which cloud provider offers the broadest range of services? Explain your answer.
> AWS generally offers the broadest range of services, with over 200 managed offerings spanning everything from core compute and storage to niche products like satellite ground stations and quantum computing sandboxes. This is a natural result of AWS being the first major public cloud provider — it has had the most time to build out specialized services for nearly every use case.

### 2️⃣ Which cloud platform would you recommend for an organization that primarily uses Microsoft products?
> Microsoft Azure would be the best fit for such an organization. Azure integrates tightly with Microsoft 365, Active Directory (now Microsoft Entra ID), and other Microsoft enterprise tools, making identity management, licensing, and workflow integration much smoother for a company already invested in the Microsoft ecosystem.

### 3️⃣ Which platform is widely recognized for Artificial Intelligence (AI), Machine Learning (ML), and Kubernetes services?
> Google Cloud Platform is widely recognized in this space — it created Kubernetes and offers Google Kubernetes Engine (GKE) as a best-in-class managed option, along with strong AI/ML tooling like Vertex AI, TPUs (Tensor Processing Units), and BigQuery ML for data analytics.

### 4️⃣ What similarities did you observe among the three cloud providers?
> All three providers offer functionally equivalent core services — virtual machines for compute, object storage for unstructured data, virtual networks for isolated environments, and IAM systems for access control. All three also follow a pay-as-you-go pricing model, support managed Kubernetes, and provide global infrastructure with regions and availability zones. The main differences lie in terminology, ecosystem integrations, and areas of specialization rather than core capability.
